# tp80 依赖台账与版本核查平台

一个本地小工具：把各个项目用到的依赖集中登记起来。页面上先建项目，再往项目下面登记依赖名称、版本、许可、责任人与状态；同一个依赖被两个项目用到时，版本高低一眼能比出来。依赖名写得不合规矩、版本不是三段数字、同一个项目里重复登记同一个依赖，保存时当场就会指出来。

依赖登记区下面还有一块版本区间设定区：可以逐条给登记写上允许的版本范围，当前登记的版本一超范围，就会在登记列表和区间列表里同时标成超界。

数据全部存在本机的数据文件里，不连数据库，也不调用任何外部服务。

## 技术栈

- 后端：Node.js（>=18）与 Express，前后端同一个进程
- 前端：原生 HTML、CSS 与 JavaScript，页面文件由后端静态目录直接提供，没有构建步骤
- 存储：本地 JSON 文件 `data/db.json`

## 启动方式

```bash
npm install
npm start
```

启动后打开页面地址：<http://localhost:5080>

端口固定为 `5080`，如需临时改动可在启动前设置环境变量 `PORT`。

## 页面怎么用

1. 顶栏右侧可以填当前操作者，填过之后浏览器会记住，新建登记时会把它带进责任人
2. 项目区列出项目名称、负责人、说明与这个项目下已经登记了多少条依赖；可以新增项目，也可以改名、换负责人、删除
3. 依赖登记区顶部可以按项目、状态、许可筛选，再按依赖名、责任人或者备注搜索，右上角刷新按钮重新拉取一次
4. 点新建登记，选好所属项目，填上依赖名称、版本，按需要补许可、责任人、状态与备注；列表里点编辑会把这条登记回填到表单
5. 依赖登记列表里有一列范围核查：这条登记设过允许范围且当前版本还在范围内显示在范围内，落在范围外显示已超界，没设过显示未设范围
6. 在下面的版本区间设定区点为登记设定区间，选一条登记，挑一种范围写法并填好端点；列表里点改写会把这条区间回填到表单，点清除则整段删掉
7. 任何一步不成立时，页面顶部给出说明，并尽量把问题标到对应的输入项上；删除项目、删除登记与清除区间都会先确认

项目下面还挂着依赖登记时不允许删除项目，页面上会写清还剩多少条、例如哪几条，先处理这些登记再删。删除依赖登记时，挂在它上面的区间会一并清除。

## 区间口径

一条登记最多只有一段允许范围，重复保存就是把原来的整段改写。范围写法有四种：

- **不低于某个版本**：只填下限，可指定下端点是包含（`≥`）还是不包含（`>`）
- **不高于某个版本**：只填上限，可指定上端点是包含（`≤`）还是不包含（`<`）
- **落在两个版本之间**：下限、上限都要填，两端含不含各自独立指定；展示时方括号表示含端点、圆括号表示不含，例如 `[18.0.0, 19.0.0)`
- **只允许某一段主版本号**：只填一个数字，例如 `5` 表示允许 `5.x` 的全部版本

端点版本允许写成一到三段数字（登记版本固定三段，少的段按 0 补齐），例如 `1.72` 与 `1.72.0` 等价，也允许带预发布后缀；预发布版本排在同号正式版前面，所以 `5.0.0-rc.1` 不满足不低于 `5.0.0`。下限不能高于上限，下限与上限相同又有任一端不含时会被挡下。区间说明最长 200 个字符，可以留空。

## 登记口径

- 依赖名称以小写字母或数字开头，可以用小写字母、数字、点、下划线、短横线与斜线，最长 60 个字符；带范围的写法例如 `@types/node` 也按这个口径登记
- 版本写成三段数字，例如 `2.7.18`，需要时可以带一段预发布后缀，例如 `5.0.10-rc.1`
- 许可按实际名称填写，例如 `MIT`、`Apache-2.0`、`BSD-3-Clause`；还没确认的可以留空，列表里会显示成未填
- 责任人可以留空，表示这条依赖还没有定人
- 状态只有三种：在用、待升、已弃用
- 备注用来写为什么用这个版本、有没有待办，最长 200 个字符
- 同一个项目下不允许出现同名的依赖，同一个依赖在不同项目里各登记各的、互不覆盖

## 数据存储

所有数据写在 `data/db.json`，结构为 `{ "projects": [...], "deps": [...], "ranges": [...] }`。落盘时先把内容写进同名临时文件，再用改名的方式替换正式文件，写入过程中断也不会把数据文件写坏；文件缺失或内容损坏时会自动回落到初始数据。整理结构时类型不认识、主版本号不是非负整数的区间会被丢掉，指向已删除登记的区间也会一并清掉。

## 接口一览

| 方法   | 路径                | 说明                                             |
| ------ | ------------------- | ------------------------------------------------ |
| GET    | /api/health         | 服务状态检查                                     |
| GET    | /api/projects       | 项目清单，附带每个项目的依赖条数                 |
| POST   | /api/projects       | 新增项目                                         |
| PATCH  | /api/projects/:id   | 修改项目的名称、负责人或说明                     |
| DELETE | /api/projects/:id   | 删除项目                                         |
| GET    | /api/deps           | 依赖登记列表，支持按项目、状态、许可筛选与关键词搜索 |
| POST   | /api/deps           | 新增依赖登记                                     |
| GET    | /api/deps/:id       | 查看单条依赖登记                                 |
| PATCH  | /api/deps/:id       | 修改依赖登记                                     |
| DELETE | /api/deps/:id       | 删除依赖登记（挂在它上面的区间一并清除）         |
| GET    | /api/ranges         | 区间清单，附带对应登记的项目、名称、当前版本与是否在范围内 |
| PUT    | /api/ranges         | 按登记保存区间（同一条登记重复提交即为改写）     |
| DELETE | /api/ranges/:id     | 删除单条区间设定                                 |

接口出错时统一返回 `{ "error": { "code": "...", "message": "...", "field": "..." } }`，其中 `field` 用于让页面把问题标到具体的输入项上。
